# auto-hh-cli

Автоматизация поиска, отбора и отклика на вакансии **hh.ru**: поиск через публичный API, отсев «мусора» локальным фильтром, оценка пригодности ИИ-судьёй, генерация персональных сопроводительных и автоотклик через браузер (Playwright).

> ⚠️ **Важно.** Соискательский API hh.ru закрыт (15.12.2025), поэтому отклики выполняются через **Playwright** (браузерную автоматизацию). Это нарушает пользовательское соглашение hh.ru и может привести к блокировке аккаунта. Используйте на свой страх и риск — лучше с тестового аккаунта и без агрессивных интервалов.

---

## Как это работает

Один полный цикл «поиск → отклик» состоит из двух шагов:

1. **`search`** — собрать вакансии с hh.ru, отфильтровать, оценить ИИ и сгенерировать письма → **дайджест** (файл + MongoDB).
2. **`apply`** — открыть сохранённую сессию браузера и откликнуться на вакансии из дайджеста.

```
hh.ru ──API──▶ search: сбор вакансий
                 │
                 ├─▶ локальный фильтр (навыки, исключения, ЗП) ── пропуск
                 ├─▶ ИИ-судья: score 1–10, вердикт fit/no-fit
                 ├─▶ генерация сопроводительного под вакансию
                 ▼
             дайджест (digest-ГГГГ-ММ-ДД.md + MongoDB)
                 │
                 ▼
apply ──Playwright──▶ браузер (сохранённая сессия) → отклики на hh.ru
```

## Установка

Требования: **Node.js 18+**, запущенный **MongoDB** (проще всего через `docker-compose`).

```bash
# 1. Зависимости и браузер Playwright
npm install
npx playwright install chromium

# 2. Конфигурация
cp .env.example .env          # затем заполните .env (см. ниже)
# config.json уже есть в репозитории — отредактируйте его под себя

# 3. MongoDB (опционально, если нет своего инстанса)
docker compose up -d          # поднимет mongo + mongo-express (localhost:8081, admin/admin)

# 4. Применить миграции MongoDB (индексы, коллекции)
npm run migrate:up

# 5. Резюме
#    Один файл:  задайте RESUME_PATH=./resume.md в .env
#    Несколько:  RESUMES_DIR=./resumes (каждый файл .md/.txt/.pdf = отдельное резюме)
```

Запуск не требует компиляции — CLI исполняет TypeScript напрямую через `tsx`. Скрипт `npm run build` (`tsc`) нужен только если вы собираете чистый JS.

## Резюме

Инструменту нужно ваше резюме — ИИ читает его и сравнивает с каждой вакансией (оценка пригодности и сопроводительные). Поддерживаются форматы `.md`, `.txt`, `.pdf`.

### Шаг 1 — положите файл резюме

Создайте директорию `resumes/` в корне проекта и положите туда резюме:

```
resumes/ivan.md
```

### Шаг 2 — укажите резюме в `.env`

Два режима:

| Режим | Переменная | Описание |
| --- | --- | --- |
| Одно резюме | `RESUME_PATH=./resume.md` | Путь к одному файлу |
| Несколько | `RESUMES_DIR=./resumes` | Директория; имя файла без расширения = ключ для `--resume <name>` |

> ⚠️ Код читает переменную **`RESUMES_DIR`** (с «S»), хотя в `.env.example` указана `RESUME_DIR` — скопировав пример как есть, режим нескольких резюме не заработает. Либо переименуйте, либо задайте обе.

### Шаг 3 — поднимите MongoDB и примените миграции

```bash
docker compose up -d
npm run migrate:up
```

### Шаг 4 — зарегистрируйте резюме в базе

Регистрация добавляет резюме в коллекцию `resumes` MongoDB — это привязка вердиктов ИИ, сопроводительных и кэша к конкретному резюме через `resumeId`.

Регистрация происходит **автоматически** при первом запуске поиска с загруженным резюме:

```bash
npm start
```

Либо **вручную** (`<имя>` — имя файла без расширения; файл должен лежать в `RESUMES_DIR`):

```bash
npm run resume:list                      # показать доступные резюме
npm run resume:show -- ivan             # показать содержимое resumes/ivan.md
npm run resume:register -- ivan         # зарегистрировать resumes/ivan.md
```

То же самое напрямую через CLI:

```bash
npx auto-hh resume list
npx auto-hh resume show ivan
npx auto-hh resume register ivan
```

> В базу сохраняются только метаданные — `resumeId`, `name`, `filename`, `createdAt`. **Сам текст резюме в MongoDB не загружается**: он всегда читается из файла на диске при каждом запуске.

## Быстрый старт

```bash
# 1. Войти на hh.ru — откроется браузер, залогиньтесь вручную и закройте его.
#    Сессия сохранится в ./data/browser-profile
npm run login

# 2. Собрать дайджест: поиск → фильтр → ИИ-судья → сопроводительные
npm start

# 3. Посмотреть, что отобралось
npx auto-hh digest            # или: npm start --dry-run для повторного прогона

# 4. Откликнуться на всё из дайджеста
npm run apply
```

**Во время `apply`** скрипт для каждой вакансии сам заполняет сопроводительное, но **финальную кнопку «Откликнуться» вы нажимаете вручную** в браузере — это защита от случайных откликов. Если на вакансии есть тестовое задание, по умолчанию (`PW_TEST_MODE=manual`) скрипт приостановится, а вы пройдёте тест и нажмёте ENTER в консоли.

### npm-скрипты

| Скрипт | Эквивалент CLI | Что делает |
| --- | --- | --- |
| `npm start` | `auto-hh search` | Основной прогон → дайджест |
| `npm run apply` | `auto-hh apply` | Отклики из дайджеста через Playwright |
| `npm run login` | `auto-hh apply --login` | Открыть браузер и войти на hh.ru |
| `npm run schedule` | `auto-hh schedule` | Планировщик: `search` по расписанию |
| `npm run resume:list` | `auto-hh resume list` | Показать список резюме |
| `npm run resume:show` | `auto-hh resume show [name]` | Показать резюме: `npm run resume:show -- <имя>` |
| `npm run resume:register` | `auto-hh resume register <name>` | Зарегистрировать резюме: `npm run resume:register -- <имя>` |
| `npm run build` | — | Компиляция TS в JS (не обязательна) |
| `npm run migrate:up` | — | Применить миграции MongoDB |
| `npm run migrate:down` | — | Откатить последнюю миграцию |
| `npm run migrate:create` | — | Создать новую миграцию |

### CLI (`auto-hh <command>` / `npx auto-hh <command>`)

| Команда | Что делает |
| --- | --- |
| `auto-hh search` | Поиск, фильтр, ИИ-судья, письма → **дайджест**. См. флаги ниже |
| `auto-hh apply` | Откликнуться на вакансии из дайджеста через Playwright |
| `auto-hh apply --login` | Режим логина (то же, что `npm run login`) |
| `auto-hh schedule` | Запустить планировщик — выполняет `search` по cron из `config.json` |
| `auto-hh digest` | Показать последний дайджест (`-j` — в JSON) |
| `auto-hh history` | Показать историю откликов (`-j` — в JSON) |
| `auto-hh config` | Показать текущую конфигурацию (`config.json`) |
| `auto-hh reset` | Сбросить историю, кэш и дайджесты (файлы + MongoDB) |
| `auto-hh cover <vacancyId>` | Сгенерировать сопроводительное для одной вакансии по id |
| `auto-hh grade` | Оценить резюме ИИ «глазами рекрутера» → `resume-grade.md` |
| `auto-hh resume list` | Показать список резюме из `RESUMES_DIR` |
| `auto-hh resume show [name]` | Показать метаданные и содержимое резюме (без имени — дефолтное) |
| `auto-hh resume register <name>` | Зарегистрировать резюме в MongoDB (авто при первом `search`) |

### Флаги `search`

| Флаг | Что делает |
| --- | --- |
| `-c, --config <path>` | Альтернативный путь к `config.json` |
| `-d, --dry-run` | Поиск и отбор, но **без** генерации сопроводительных |
| `--no-claude` | Без ИИ — только локальный фильтр (нужно резюме не требуется) |
| `--reset` | Перед запуском сбросить историю, кэш и дайджесты |
| `-r, --resume <name>` | Выбрать конкретное резюме из `RESUMES_DIR` по имени (без расширения) |

### Флаги `apply`

| Флаг | Что делает |
| --- | --- |
| `-l, --limit <n>` | Обработать только первые `n` вакансий из дайджеста |
| `-t, --type <type>` | `latest` — только сегодняшний дайджест (по умолчанию), `all` — все дни |
| `--login` | Режим логина: открыть браузер и дождаться ручного входа на hh.ru |

## config.json

```text
{
  "search": { ... },     // запрос к API hh.ru
  "filter": { ... },     // локальный пре-фильтр
  "apply":  { ... },     // пороги и шаблоны
  "api":    { ... },     // ИИ-провайдер (OpenAI-совместимый)
  "schedule": { ... },   // cron для `auto-hh schedule`
  "adaptResume": true    // адаптировать резюме под вакансию перед письмом
}
```

### `search` — запрос к hh.ru

| Поле | Что задаёт |
| --- | --- |
| `text` | Поисковая строка (поддерживает `OR`, `AND`, скобки) |
| `area` | ID региона hh — `null` = вся Россия, `[1, 2]` = список регионов |
| `experience` | Опыт: `between1And3`, `between3And6`, … |
| `salary` | Минимальная ЗП |
| `currency` | `RUR`, `USD`, … |
| `only_with_salary` | Только вакансии с указанной ЗП |
| `schedule` | График: `remote`, `flexible`, … |
| `employment` | Занятость: `full`, `part`, `project`, … |
| `per_page` | Вакансий на странице (≤ 100) |
| `start_page` | С какой страницы начинать (0 = первая) |
| `max_pages` | Сколько страниц обойти, считая от `start_page` |

### `filter` — локальный пре-фильтр

| Поле | Что задаёт |
| --- | --- |
| `requiredSkills` | Список — хотя бы один навык должен встретиться в описании |
| `excludedKeywords` | Слова, при наличии которых вакансия отбрасывается |
| `excludedCompanies` | Компании, которые игнорируем |
| `excludeArchived` | Пропускать архивные вакансии |

### `apply` — пороги и шаблоны

| Поле | Что задаёт |
| --- | --- |
| `maxPerRun` | Максимум вакансий в один дайджест |
| `dryRun` | Если `true` — письма не генерируются (эквивалент флага `--dry-run`) |
| `minClaudeScore` | Нижний порог score ИИ-судьи, всё ниже отбрасывается |
| `coverLetterTemplate` | Фолбэк-шаблон письма, если ИИ недоступен. Плейсхолдеры: `{title}`, `{employer}`, `{area}`, `{signature}` (подпись из `COVER_SIGNATURE`) |

### `api` — ИИ-провайдер

| Поле | Что задаёт |
| --- | --- |
| `baseUrl` | Базовый URL OpenAI-совместимого API (по умолчанию — DeepSeek) |
| `apiKey` | Ключ. Запасные источники: `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` в `.env` |

Если ключ не задан — ИИ-судья и генерация писем выключаются, остаётся только локальный фильтр.

### `schedule`

| Поле | Что задаёт |
| --- | --- |
| `cron` | Cron-выражение (5 полей). Пример: `0 12 * * *` — каждый день в 12:00 |

### `adaptResume`

Булевый флаг: адаптировать резюме под конкретную вакансию перед генерацией сопроводительного (`true` по умолчанию).

## Переменные окружения (`.env`)

### Базовые

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `CONFIG_PATH` | `./config.json` | Альтернативный путь к конфигу |
| `HH_USER_AGENT` | `AutoHH/1.0` | User-Agent для API hh.ru — рекомендуется указать ваш email |
| `RESUME_PATH` | — | Путь к **одному** резюме (`.txt`, `.md`, `.pdf`) |
| `RESUMES_DIR` | — | Директория с **несколькими** резюме. Выбор: `search --resume <name>` |
| `APPLICANT_PROFILE` | `опытный разработчик` | Краткое описание соискателя — попадает в системный промпт ИИ |
| `REQUEST_DELAY_MS` | `1500` | Пауза между запросами к API hh.ru |
| `MONGODB_URI` | `mongodb://localhost:27017/autohh` | URI MongoDB для кэша, истории и дайджестов |
| `DEBUG` | — | Любое непустое значение включает `log.debug` |

> ⚠️ Код читает переменную **`RESUMES_DIR`**, хотя в `.env.example` до сих пор указана `RESUME_DIR` (опечатка). Если копируете `.env.example` как есть — режим нескольких резюме не заработает. Либо переименуйте, либо задайте обе.

### ИИ

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | — | Запасной ключ, если нет `api.apiKey` в `config.json` |
| `OPENAI_API_KEY` | — | То же, второй запасной вариант |
| `CLAUDE_MODEL` | `gpt-4o` | Модель для судьи и писем. **Должна** соответствовать `api.baseUrl` (для DeepSeek — например `deepseek-chat`) |
| `JUDGE_BATCH_SIZE` | `10` | Сколько вакансий в одной пачке на судейство |
| `COVER_BATCH_SIZE` | `20` | Сколько писем генерировать за один запрос |
| `COVER_SIGNATURE` | `Telegram: <your-telegram>, e-mail: <your-email>` | Подпись сопроводительного письма — идёт в системный промпт ИИ и в плейсхолдер `{signature}` шаблона из `config.json` |

### Playwright (`apply` / `login`)

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `PW_USER_DATA_DIR` | `./data/browser-profile` | Где хранится профиль браузера (cookies, сессия) |
| `PW_HEADLESS` | `false` | `true` для работы без окна браузера |
| `PW_MIN_DELAY_MS` | `500` | Нижняя граница рандомной паузы между откликами |
| `PW_MAX_DELAY_MS` | `2000` | Верхняя граница |
| `PW_TEST_MODE` | `manual` | `manual` — пауза на тесте, ждать ENTER в консоли; `skip` — пропускать вакансии с тестом |
| `PW_TEST_TIMEOUT_MS` | `0` | Таймаут ожидания ENTER в manual-режиме (0 = без таймаута) |
| `PW_MANUAL_TIMEOUT_MS` | `300000` | Сколько ждать ручного нажатия «Откликнуться» на одной вакансии |

### Зарезервировано (не используется в основном потоке)

`HH_CLIENT_ID`, `HH_CLIENT_SECRET`, `HH_REDIRECT_URI`, `HH_ACCESS_TOKEN`, `HH_REFRESH_TOKEN`, `HH_RESUME_ID` — для OAuth-сценария (`src/oauth-server.js`). Не задействованы, т.к. соискательский API закрыт.

## Файлы в `data/`

| Файл / коллекция | Что в нём |
| --- | --- |
| `history.json` (+ MongoDB `history`) | Какие вакансии уже видели / на какие откликались |
| MongoDB `cachePages`, `cacheFull`, `cacheJudgements`, `cacheCoverLetters` | Кэш за текущую дату: страницы поиска, карточки, вердикты ИИ, письма. Позволяет продолжить после обрыва, не запрашивая hh.ru и не пересудя заново |
| `digest-ГГГГ-ММ-ДД.md` (+ MongoDB `digest`) | Подходящие вакансии с сопроводительными |
| `rejected-ГГГГ-ММ-ДД.md` (+ MongoDB `rejected`) | Вакансии, отбракованные ИИ, с причинами |
| `browser-profile/` | Профиль Chromium (cookies, localStorage) |
| `apply-dom-*.html` | Дамп DOM, если Playwright не нашёл поле для письма |
| `app.log` | Лог |

## Замечания и отладка

- **Селекторы hh.ru меняются** — если автоотклик перестал работать, смотрите `data/app.log` и обновите массивы `respondSelectors`, `submitSelectors` и т.п. в `src/apply-playwright.ts`.
- **Тесты в вакансии.** По умолчанию (`PW_TEST_MODE=manual`) скрипт ставит окно браузера на передний план и ждёт ENTER в консоли — проходите тест вручную, отправляете отклик, затем ENTER → следующая вакансия. Режим `skip` пропускает такие вакансии. Ручной режим работает только при `PW_HEADLESS=false`.
- **Ручное подтверждение отклика.** `apply` заполняет письмо, но не жмёт кнопку сам — вы нажимаете «Откликнуться» в браузере (защита от случайного). Таймаут ожидания — `PW_MANUAL_TIMEOUT_MS`.
- **Лимит hh.ru** — ~200 откликов в день, не превышайте (задаётся `maxPerRun`).
- **ИИ без ключа.** Без `api.apiKey` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` судья и письма отключаются — работает только локальный фильтр.
- **Модель и провайдер должны совпадать**: `CLAUDE_MODEL` выбирается под `api.baseUrl` (DeepSeek → `deepseek-chat`, OpenAI → `gpt-4o` и т.д.).
